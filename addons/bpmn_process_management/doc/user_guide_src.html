ბიზნესპროცესების მართვა (BPMN)

მომხმარებლის სახელმძღვანელო · Odoo 19 და 20 · Community და Enterprise

1. რა არის მოდული

მოდული არის კომპანიის პროცესების ოფიციალური, ინტერაქტიული რუკა Odoo-ს შიგნით. ნებისმიერი თანამშრომელი ხედავს, ვინ, რას, რა თანმიმდევრობით აკეთებს; ამოცანაზე დაწკაპუნებით კითხულობს სამუშაო ინსტრუქციას და ერთი ღილაკით გადადის Odoo-ს შესაბამის ეკრანზე. პროცესების მენეჯერები ხაზავენ, აიმპორტებენ და ამტკიცებენ პროცესებს.

მოდული არ ბლოკავს Odoo-ს ღილაკებს და არ ცვლის გაყიდვების, შესყიდვების, საწყობისა თუ ინვოისების სტატუსებს. ის მხოლოდ აღწერს და მიმართულებას აძლევს.

2. როლები

როლივის ენიჭებარა შეუძლია
დამთვალიერებელიყველა შიდა მომხმარებელს ავტომატურადხედავს მხოლოდ გამოქვეყნებულ პროცესებს, კითხულობს ინსტრუქციებს, ხსნის ბმულებს, ჩამოტვირთავს დიაგრამას.
პროცესების მენეჯერიადმინისტრატორი ანიჭებს: პარამეტრები → მომხმარებლები → ბიზნესპროცესები → პროცესების მენეჯერიქმნის და ხაზავს პროცესებს, აიმპორტებს ფაილებს, ანიჭებს პასუხისმგებლებს, გზავნის განხილვაზე, აქვეყნებს, ქმნის ახალ ვერსიებს.

3. პროცესების რუკა და დათვალიერება

მენიუ პროცესები → პროცესების რუკა აჩვენებს ყველა გამოქვეყნებულ პროცესს მინიატურით, დაჯგუფებულს ტიპის მიხედვით (ძირითადი, დამხმარე, მმართველობითი).

პროცესის გახსნისას დიაგრამა ჩანართში დიაგრამა იხსნება მხოლოდ სანახავად:

  • გადიდება/დაპატარავება — მაუსის ბორბალი + Ctrl ან ღილაკები ზედა ზოლში; გადაადგილება — მაუსის გადათრევა;
  • ეკრანზე მორგება — მთელი დიაგრამის ჩვენება; სრული ეკრანი — Esc ხურავს;
  • დააწკაპუნეთ ამოცანაზე: მარჯვნივ გამოჩნდება ბარათი — ზოლი, პასუხისმგებელი, სამუშაო ინსტრუქცია და ბმულები. ფიგურის ქვედა კუთხეში მწვანე ნიშანი 🔗 ნიშნავს, რომ მას ბმული აქვს.

ბარათზე ბმულის ღილაკი ხსნის შესაბამის Odoo-ს მენიუს, დოკუმენტს ან ვებგვერდს. თუ ბმული გაწყვეტილია ან მასზე წვდომა არ გაქვთ, ღილაკი წითელია და არ მუშაობს.

ძიება: საძიებო ველში შეგიძლიათ მოძებნოთ პროცესი სახელით, კოდით, დიაგრამის ელემენტით (მაგ. „ინვოისი“) ან პასუხისმგებლით (მაგ. „საწყობი“) — ნაპოვნი იქნება ყველა პროცესი, სადაც ეს დეპარტამენტი მონაწილეობს. მენიუ პასუხისმგებლობები აჩვენებს, რომელი ზოლი რომელ დეპარტამენტს ეკუთვნის ყველა პროცესში.

4. პროცესის დახაზვა (პროცესების მენეჯერი)

  1. ყველა პროცესი → ახალი. შეავსეთ დასახელება, კოდი (მაგ. SCM-07), ტიპი, მფლობელი, მშობელი პროცესი (თუ ეს ქვეპროცესია).
  2. დიაგრამა ჩანართში იხსნება რედაქტორი (ზედა ზოლში წარწერა რედაქტირება). მარცხენა პალიტრიდან გადმოათრიეთ ფიგურები.
  3. ფიგურაზე დაწკაპუნებისას მის გვერდით ჩნდება სწრაფი მენიუ (context pad): შემდეგი ამოცანის/შლუზის/მოვლენის მიერთება, დაკავშირება, წაშლა და 🔧 ელემენტის შეცვლა.
  4. ტექსტის შესაცვლელად ორჯერ დააწკაპუნეთ ფიგურაზე ან გამოიყენეთ მარჯვენა პანელის ველი „სახელი“.
  5. ცვლილებები ფორმაში ავტომატურად გადადის; შეინახეთ ჩვეულებრივად (ღრუბლის ხატულა ფორმის სათაურთან ან Alt+S).
აუზი და ზოლები: პალიტრიდან დასვით „აუზი/მონაწილე“; აუზზე დაწკაპუნებით context pad-ში გამოჩნდება „ზოლის დამატება ზემოთ/ქვემოთ“, „ორ/სამ ზოლად დაყოფა“. ყოველი ზოლი ჩვეულებრივ ერთი დეპარტამენტი ან როლია.

5. BPMN ელემენტები

მხარდაჭერილია BPMN 2.0-ის პროცესისა და კოლაბორაციის დიაგრამის ყველა ელემენტი. ხშირად გამოყენებადები პირდაპირ პალიტრაშია, დანარჩენი — 🔧 ელემენტის შეცვლა მენიუდან.

ჯგუფიპალიტრაში🔧 „ელემენტის შეცვლა“-დან დამატებით
მოვლენებისაწყისი, შუალედური, დასასრული; შეტყობინების და ტაიმერის საწყისი, შეტყობინების/ტაიმერის მოლოდინი, შეტყობინების/შეცდომის/შეწყვეტის დასასრულიპირობითი, სიგნალის, ესკალაციის, კომპენსაციის, გაუქმების, ბმის, მრავლობითი, პარალელური მრავლობითი; სასაზღვრო (interrupting / non-interrupting)
შლუზებიგამომრიცხავი (XOR), პარალელური (AND), ჩამრთველი (OR), მოვლენაზე დაფუძნებულიკომპლექსური
აქტივობებიამოცანა, მომხმარებლის, ხელით, სერვისის, გაგზავნის, მიღების, ბიზნესწესის ამოცანა, გამოძახების აქტივობა, აკეცილი და გაშლილი ქვეპროცესისკრიპტის ამოცანა, მოვლენის ქვეპროცესი, Ad-hoc ქვეპროცესი, ტრანზაქცია; მარკერები: ციკლი, პარალელური და თანმიმდევრული მრავალეგზემპლარიანი, კომპენსაცია
მონაცემები და არტეფაქტებიმონაცემთა ობიექტი, მონაცემთა საცავი, ჯგუფი, ტექსტური შენიშვნა—
მონაწილეებიაუზიზოლები (აუზის context pad-იდან), ცარიელი აუზი
ნაკადებიდაკავშირების ხელსაწყოპირობითი და ნაგულისხმევი ნაკადი; აუზებს შორის ავტომატურად — შეტყობინების ნაკადი
BPMN 2.0-ის Choreography და Conversation დიაგრამები არ არის მხარდაჭერილი (bpmn-js-ის შეზღუდვა). პროცესების დოკუმენტირებისთვის ისინი პრაქტიკულად არ გამოიყენება.

6. ინსტრუქციები, ბმულები, პასუხისმგებლები

სამუშაო ინსტრუქცია

მონიშნეთ ფიგურა და მარჯვენა პანელში შეავსეთ სამუშაო ინსტრუქცია: რა უნდა გაკეთდეს, რა წესი მოქმედებს, რა კონტროლი ტარდება. ტექსტი ინახება BPMN-ის სტანდარტულ documentation ველში, ამიტომ Camunda-სა და Signavio-შიც ჩანს.

ბმულები

პანელის ბმულები ნაწილში აირჩიეთ ტიპი და მოძებნეთ ობიექტი:

  • Odoo-ს მენიუ — მაგ. „გაყიდვები / შეკვეთები / ციტირებები“. თანამშრომელი ხედავს მხოლოდ მისთვის ხელმისაწვდომ მენიუებს.
  • ჩანაწერი — სხვა ბიზნესპროცესი, დანართი; Enterprise-ში ასევე Knowledge სტატია და Documents დოკუმენტი (ჩანს მხოლოდ, თუ აპლიკაცია დაინსტალირებულია).
  • ვებმისამართი (URL) — https://, http://, mailto: ან Odoo-ს შიდა /… ბმული.

პასუხისმგებელი (ზოლისთვის)

მონიშნეთ ზოლი (ან აუზი, თუ ზოლები არ აქვს) და პასუხისმგებელი ნაწილში აირჩიეთ დეპარტამენტი, თანამდებობა (საჭიროა Employees აპლიკაცია), მომხმარებელთა ჯგუფი ან მომხმარებელი. ზოლის ყველა ამოცანა ამ პასუხისმგებლობას იღებს.

ბმულები ინახება ტექნიკური იდენტიფიკატორითაც (XML ID). ამიტომ სხვა ბაზაში გადატანის შემდეგ სტანდარტული მენიუები ისევ სწორად იხსნება, ხოლო რაც ვერ მოიძებნა, დიაგრამაზე მოინიშნება როგორც გაწყვეტილი.

7. იმპორტი: draw.io, Visio, BPMN

პროცესები → დიაგრამის იმპორტი (ან დრაფტის ფორმაზე ღილაკი დიაგრამის იმპორტი — არსებული დიაგრამის ჩასანაცვლებლად).

წყაროროგორ მოვამზადოთ ფაილი
draw.io / diagrams.netFile → Save as → .drawio (ან .xml). გამოდგება File → Export as → SVG / PNG, თუ მონიშნულია „Include a copy of my diagram“. მრავალგვერდიან ფაილში თითოეული გვერდი ცალკე პროცესი ხდება (ან აირჩიეთ „მხოლოდ პირველი გვერდი“).
Microsoft VisioFile → Save As → Visio Drawing (*.vsdx). ძველი .vsd ჯერ უნდა შეინახოთ .vsdx-ად.
Camunda Modeler, Signavio, bpmn.io, Bizagi, ARIS…BPMN 2.0 XML ექსპორტი (.bpmn). თუ ფაილს განლაგება არ აქვს, გახსნისას ავტომატურად განლაგდება.

რას ცნობს გადამყვანი

  • draw.io-ს BPMN 2.0 ბიბლიოთეკის ყველა ფიგურას (ამოცანების ტიპები, მოვლენები განმარტებებით, შლუზები, ქვეპროცესები, ციკლის მარკერები, მონაცემები, ჯგუფი, შენიშვნა), swimlane-ებს, Cross-Functional Flowchart-ს;
  • Visio-ს BPMN Diagram შაბლონის ფიგურებს (shape data-ს მიხედვით), Cross-Functional Flowchart ზოლებს, Basic Flowchart-ს;
  • ჩვეულებრივ ნახაზებს: მართკუთხედი → ამოცანა, რომბი → გამომრიცხავი შლუზი, წრე/ოვალი → მოვლენა (საწყისი/დასასრული კავშირების მიხედვით), დოკუმენტი → მონაცემთა ობიექტი, ცილინდრი → მონაცემთა საცავი, ტექსტი → შენიშვნა.

რა ხდება იმპორტის შემდეგ

  1. ზოლები ედარება დეპარტამენტებს, თანამდებობებს და ჯგუფებს ზუსტად იმავე სახელით. ნაპოვნი ავტომატურად მიებმება.
  2. ყველა ზოლი ინიშნება ! ნიშნით: ან „დაადასტურეთ ავტომატური შერჩევა“, ან „მიანიჭეთ დეპარტამენტი / როლი“. ვარაუდით განსაზღვრული ფიგურებიც ინიშნება („შეამოწმეთ ელემენტის ტიპი“).
  3. chatter-ში იწერება ანგარიში: რა გარდაიქმნა, რა გამოტოვდა და რატომ (მაგ. შემაერთებელი, რომელიც ფიგურაზე არ იყო მიმაგრებული).
რჩევა უკეთესი შედეგისთვის: draw.io-ში გამოიყენეთ More Shapes → BPMN 2.0 ბიბლიოთეკა და შემაერთებლები ფიგურებზე მიამაგრეთ (ლურჯი ჯვარი/წერტილი). Visio-ში გამოიყენეთ BPMN ან Cross-Functional Flowchart შაბლონი. ზოლებს დაარქვით ზუსტად Odoo-ს დეპარტამენტის სახელი — მაშინ ისინი ავტომატურად მიებმება.

ზოლების შესაბამისობის თავიდან გასაშვებად (მაგ. დეპარტამენტების შექმნის შემდეგ) დრაფტზე დააჭირეთ ზოლების შესაბამისობა.

8. გადასახედი რიგი

მენიუ გადასახედი რიგი აგროვებს ყველა პროცესის მონიშნულ ელემენტს: რა უნდა გაკეთდეს და სად. გახსნა გადაგიყვანთ პროცესზე და პირდაპირ ამ ელემენტს მონიშნავს.

დიაგრამაში ღილაკი ⚠ გადასახედია: N თანმიმდევრულად გადადის მონიშნულ ელემენტებზე. შესწორების შემდეგ დააჭირეთ გადახედულად მონიშვნა; ზოლზე პასუხისმგებლის არჩევისას ნიშანი თავად იხსნება. ნიშნებს ხედავს მხოლოდ პროცესების მენეჯერი.

11. ხშირი კითხვები და შეზღუდვები

რატომ არ ჩანს ჩემი პროცესი რუკაზე?

რუკაზე მხოლოდ გამოქვეყნებული პროცესებია. დრაფტები და განხილვაში მყოფი ვერსიები ჩანს ყველა პროცესი მენიუში (მხოლოდ მენეჯერებს).

რატომ არ შემიძლია დიაგრამის შეცვლა?

რედაქტირება შესაძლებელია მხოლოდ დრაფტში და მხოლოდ პროცესების მენეჯერისთვის. გამოქვეყნებულის შესაცვლელად შექმენით ახალი ვერსია.

ყველაფერი ზუსტად გადმოვა draw.io-დან/Visio-დან?

BPMN ბიბლიოთეკით დახაზული ნახაზი — თითქმის სრულად. თავისუფალი ნახაზის დროს მოდული ფიგურის ტიპს ვარაუდობს და ასეთ ფიგურებს გადასახედად ნიშნავს. ფერები, შრიფტები და ხაზების ზუსტი მოხვევები არ გადმოდის: BPMN სტანდარტი მათ არ ინახავს. ჩვეულებრივ დასჭირდება რამდენიმე წუთი ხელით გასწორება.

რა არ არის მხარდაჭერილი

  • Visio-ს ძველი .vsd ფორმატი (შეინახეთ .vsdx-ად); Visio-ში ექსპორტი;
  • BPMN Choreography და Conversation დიაგრამები;
  • პროცესის ავტომატური შესრულება (ეს არ არის workflow engine — განზრახ).

რა არის „BPMN.io“ ლოგო კუთხეში?

დიაგრამის ბიბლიოთეკის (bpmn-js) ლიცენზია მოითხოვს, რომ ეს ლოგო ხილული დარჩეს. მისი დამალვა ლიცენზიას არღვევს.

12. ადმინისტრატორისთვის

  • ინსტალაცია: ფოლდერი bpmn_process_management დაამატეთ addons path-ში → Apps → Update Apps List → „BPMN Process Management“ → Install. დამატებითი Python პაკეტები არ სჭირდება.
  • როლები: ყველა შიდა მომხმარებელი ავტომატურად არის დამთვალიერებელი; პროცესების მენეჯერი ენიჭება მომხმარებლის ფორმაში.
  • ენა: ადმინისტრატორი ერთხელ ააქტიურებს ენას (Settings → Languages → Add Language), შემდეგ თითოეული მომხმარებელი ირჩევს მას My Preferences → Language-ში. მოდულის მთელი ინტერფეისი, დიაგრამის რედაქტორის პალიტრისა და მენიუების ჩათვლით, გადაირთვება. თარგმანი ინახება i18n/ka.po-ში; ახალი ენისთვის საკმარისია i18n/bpmn_process_management.pot-იდან xx.po-ს შექმნა. დიაგრამის შინაარსი (ამოცანების სახელები, ინსტრუქციები) ერთ ენაზე ინახება და არ ითარგმნება.
  • მულტიკომპანია: „კომპანია“ ცარიელი = პროცესი ყველა კომპანიისთვის; შევსებული = მხოლოდ იმ კომპანიისთვის.
  • დეპარტამენტებთან კავშირი: ჩაირთვება, თუ დაინსტალირებულია Employees (hr). Knowledge და Documents ბმულები — Enterprise-ში, თუ ეს აპლიკაციები დაყენებულია.
