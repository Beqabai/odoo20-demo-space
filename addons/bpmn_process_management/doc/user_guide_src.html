1.რა არის მოდული

მოდული არის კომპანიის პროცესების ოფიციალური, ინტერაქტიული რუკა Odoo-ს შიგნით. ნებისმიერი თანამშრომელი ხედავს, ვინ, რას და რა თანმიმდევრობით აკეთებს; ნაბიჯზე დაწკაპუნებით კითხულობს სამუშაო ინსტრუქციას და ერთი ღილაკით გადადის Odoo-ს შესაბამის ეკრანზე. პროცესების მენეჯერები ხაზავენ, აიმპორტებენ და ამტკიცებენ პროცესებს.

მოდული არ ბლოკავს Odoo-ს ღილაკებს და არ ცვლის გაყიდვების, შესყიდვების, საწყობისა თუ ინვოისების სტატუსებს. ის აღწერს, ასწავლის და მიმართულებას აძლევს — ეს არ არის workflow ძრავა.
ახალი 1.1 ვერსიაში: განახლებული რედაქტორი (ფერები, დასაკავშირებელი ფიგურების განათება, ელემენტის სწრაფი დამატება/შექმნა ძებნით, განლაგება, მინირუკა, ბადე, კლავიატურის მალსახმობები), ახალი გვერდითი პანელი და პროცესის ნაბიჯ-ნაბიჯ გავლა, პასუხისმგებლის კომენტარი და ზოლის ავტომატური სახელი, პროცესის ბარათი (SIPOC + KPI), არქიტექტურის დონეები L0–L4, თეგები, პერიოდული გადახედვა, გაცნობის დადასტურება, ფერების გადმოტანა draw.io/Visio-დან.

2.როლები

როლივის ენიჭებარა შეუძლია
დამთვალიერებელიყველა შიდა მომხმარებელს ავტომატურადხედავს მხოლოდ გამოქვეყნებულ პროცესებს, კითხულობს ინსტრუქციებს, ხსნის ბმულებს, ჩამოტვირთავს დიაგრამას, ადასტურებს გაცნობას.
პროცესების მენეჯერიადმინისტრატორი ანიჭებს: პარამეტრები → მომხმარებლები → ბიზნესპროცესები → პროცესების მენეჯერიქმნის და ხაზავს პროცესებს, აიმპორტებს ფაილებს, ანიჭებს პასუხისმგებლებს, გზავნის განხილვაზე, აქვეყნებს, ქმნის ახალ ვერსიებს, ხედავს ვინ გაეცნო.

3.რუკა და პროცესის გავლა

მენიუ პროცესები → პროცესების რუკა აჩვენებს ყველა გამოქვეყნებულ პროცესს ბარათებად: მინიატურა, დონე (L0–L4), კოდი, თეგები, ვერსია და მფლობელი. ბარათები დაჯგუფებულია ტიპის მიხედვით.

პროცესის დიაგრამა ჩანართი დამთვალიერებლისთვის სანახავად იხსნება. მარჯვნივ არის გვერდითი პანელი:

  • პროცესის მიმოხილვა (როცა არაფერია მონიშნული): ნაბიჯების, როლების და ბმულების რაოდენობა, ღილაკი ▷ პროცესის გავლა ნაბიჯ-ნაბიჯ, ნაბიჯის ძებნა და სია „ვინ რას აკეთებს“.
  • ნაბიჯის ბარათი (დაწკაპუნების შემდეგ): ვინ — ზოლი და მისი პასუხისმგებელი კომენტარით; რა უნდა გაკეთდეს — ინსტრუქცია (სიები ფორმატირებულად); Odoo-ში გახსნა — ბმულების ფილები; ნაკადი — წინა და შემდეგი ნაბიჯები. შემდეგ ნაბიჯზე დაწკაპუნებით პროცესს ბოლომდე გაივლით.
  • დიაგრამაზე მიმდინარე ნაბიჯი მწვანედ ინთება, შემდეგი ნაბიჯები — ყვითელი წყვეტილი ხაზით. მწვანე ნიშანი 🔗 ფიგურის კუთხეში ნიშნავს, რომ მას ბმული აქვს.

ბმულის ფილა ხსნის შესაბამის Odoo-ს მენიუს, ჩანაწერს ან ვებგვერდს. თუ ბმული გაწყვეტილია ან მასზე წვდომა არ გაქვთ, ფილა წითელია და არ მუშაობს.

ძიება ყველა პროცესში: საძიებო ველში მოძებნეთ სახელით, კოდით, თეგით, დიაგრამის ელემენტით (მაგ. „ინვოისი“) ან პასუხისმგებლით (მაგ. „საწყობი“). მენიუ პასუხისმგებლობები აჩვენებს, რომელი ზოლი რომელ დეპარტამენტს ეკუთვნის ყველა პროცესში.

4.დიაგრამის დახაზვა (პროცესების მენეჯერი)

  1. ყველა პროცესი → ახალი. შეავსეთ დასახელება, კოდი (მაგ. SCM-07), ტიპი, დონე, მფლობელი, მშობელი პროცესი (თუ ეს ქვეპროცესია).
  2. დიაგრამა ჩანართში იხსნება რედაქტორი (ზედა ზოლში მწვანე ნიშანი ● რედაქტირება). უფრო დიდი სივრცისთვის დააჭირეთ F ან სრული ეკრანის ღილაკს.
  3. ფიგურა გადმოათრიეთ მარცხენა პალიტრიდან, ან დააჭირეთ N და მოძებნეთ სახელით (მაგ. „ტაიმერი“).
  4. მონიშნულ ფიგურაზე დააჭირეთ A — ფანჯარაში აირჩიეთ შემდეგი ნაბიჯი, ის ავტომატურად დაიდგმება და დაუკავშირდება. იგივე შეგიძლიათ ფიგურის გვერდით მენიუდან (context pad).
  5. დასაკავშირებლად გამოიყენეთ context pad-ის ისარი (ან C): გაყვანისას მწვანედ ინთება ყველა ფიგურა, რომელთანაც კავშირი დასაშვებია BPMN-ის წესებით, საწყისი ფიგურა — ნარინჯისფრად. იგივე ხდება არსებული ისრის ბოლოს სხვა ფიგურაზე გადატანისას.
  6. ტექსტის შესაცვლელად ორჯერ დააწკაპუნეთ ფიგურაზე (ან E), ან შეცვალეთ სახელი პანელის სათაურში. ტიპის შესაცვლელად — პანელის ღილაკი ⇄ ან R.
  7. ცვლილებები ავტომატურად გადადის ფორმაში; შეინახეთ Ctrl+S-ით (Mac: ⌘+S) ან ღრუბლის ხატულით ფორმის სათაურთან.
აუზი და ზოლები: პალიტრიდან დასვით „აუზი/მონაწილე“; აუზზე დაწკაპუნებით context pad-ში გამოჩნდება „ზოლის დამატება ზემოთ/ქვემოთ“, „ორ/სამ ზოლად დაყოფა“. ყოველი ზოლი ჩვეულებრივ ერთი დეპარტამენტი ან როლია.

მიმოხილვის პანელის ხატვის რჩევები მოკლედ იმეორებს ამ ხერხებს; მალსახმობების სრული სია — ?.

5.ფერები, განლაგება, ხედი

ფერები

მონიშნეთ ერთი ან რამდენიმე ფიგურა/ისარი და პანელის სტილი ნაწილში აირჩიეთ მზა ფერი (GEC-ის პალიტრაზე დაფუძნებული: ფირუზისფერი, მუქი ლურჯი, ნარინჯისფერი, ყვითელი და სხვ.) ან საკუთარი შევსება და ხაზი და ტექსტი. ↺ აბრუნებს ნაგულისხმევს. იგივე პალიტრა ხელმისაწვდომია context pad-ის ფერის ხატულით.

ფერები ინახება BPMN-ის სტანდარტულ ფერის გაფართოებაში, ამიტომ ჩანს Camunda Modeler-სა და bpmn.io-ში, გადადის draw.io-ს ექსპორტში.

განლაგება

რამდენიმე ფიგურის მონიშვნისას (Shift+დაწკაპუნება ან ლასო L) პანელში ჩნდება განლაგება: სწორება მარცხნივ/ცენტრზე/მარჯვნივ/ზემოთ/შუაზე/ქვემოთ და თანაბარი განაწილება. ფიგურის გადათრევისას ჩნდება ნარინჯისფერი დამხმარე ხაზები, ფიგურები ბადეს ემაგრება. S (სივრცის ხელსაწყო) ამატებს ან აშორებს ადგილს ფიგურებს შორის.

ხედი

  • მასშტაბი — ქვედა მარცხენა ღილაკები, Ctrl+მაუსის ბორბალი; პროცენტზე დაწკაპუნება = 100%; 0 — ეკრანზე მორგება;
  • მინირუკა (M) — დიდ დიაგრამაში ორიენტაციისთვის; ბადე (G); გვერდითი პანელი (P) — იმალება, თუ მეტი ადგილი გჭირდებათ. არჩევანი ბრაუზერში ინახება.

7.BPMN ელემენტები

მხარდაჭერილია BPMN 2.0-ის პროცესისა და კოლაბორაციის დიაგრამის ყველა ელემენტი. ხშირად გამოყენებადები პირდაპირ პალიტრაშია, ყველა დანარჩენი — N/A ძებნით ან ტიპის შეცვლით (R).

ჯგუფიპალიტრაშიდამატებით (ძებნა / ტიპის შეცვლა)
მოვლენებისაწყისი, შუალედური, დასასრული; შეტყობინების და ტაიმერის საწყისიშეტყობინების, ტაიმერის, პირობითი, სიგნალის, ესკალაციის, შეცდომის, კომპენსაციის, გაუქმების, ბმის, შეწყვეტის, მრავლობითი; სასაზღვრო (წყვეტადი / უწყვეტი)

მონაცემები და არტეფაქტებიმონაცემთა ობიექტი და საცავი, ჯგუფი, ტექსტური შენიშვნა—

8.ინსტრუქცია, ბმულები, პასუხისმგებელი

სამუშაო ინსტრუქცია

მონიშნეთ ფიგურა და პანელში შეავსეთ სამუშაო ინსტრუქცია: რა უნდა გაკეთდეს, რა წესი მოქმედებს, რა კონტროლი ტარდება. სტრიქონი, რომელიც --ით იწყება, დამთვალიერებელს სიად უჩანს; 1. — დანომრილ სიად. ტექსტი ინახება BPMN-ის სტანდარტულ documentation ველში, ამიტომ Camunda-სა და Signavio-შიც ჩანს.

ბმულები

პანელის ბმულები ნაწილში აირჩიეთ ტიპი და მოძებნეთ ობიექტი:

  • Odoo-ს მენიუ — მაგ. „გაყიდვები / შეკვეთები“. თანამშრომელი ხედავს მხოლოდ მისთვის ხელმისაწვდომ მენიუებს.
  • ჩანაწერი — სხვა ბიზნესპროცესი, დანართი; Enterprise-ში ასევე Knowledge სტატია და Documents დოკუმენტი (ჩანს, თუ აპლიკაცია დაინსტალირებულია).
  • ვებმისამართი (URL) — https://, http://, mailto: ან Odoo-ს შიდა /… ბმული.

პასუხისმგებელი (ზოლისთვის) — სახელი და კომენტარი

მონიშნეთ ზოლი (ან აუზი, თუ ზოლები არ აქვს) და პასუხისმგებელი ნაწილში მოძებნეთ დეპარტამენტი, თანამდებობა (საჭიროა Employees აპლიკაცია), მომხმარებელთა ჯგუფი ან მომხმარებელი. ზოლის ყველა ნაბიჯი ამ პასუხისმგებლობას იღებს.

  • ზოლის სახელი ავტომატურად ხდება პასუხისმგებლის სახელი, თუ ზოლი უსახელოა, ან მისი სახელი ემთხვეოდა წინა პასუხისმგებელს. სხვა შემთხვევაში (მაგ. ზოლს ჰქვია „ცვლის ხელმძღვანელი“, პასუხისმგებელი კი „საწყობი“) სახელი არ იცვლება და ჩნდება ღილაკი ზოლის სახელად „…“-ის გამოყენება.
  • ალამი „ზოლის სახელი პასუხისმგებლის სახელს მიჰყვება“ აკავშირებს ორივეს: თუ დეპარტამენტს Odoo-ში გადაარქმევენ, პანელი ახალ სახელს აჩვენებს და ერთი დაწკაპუნებით განაახლებთ ზოლსაც.
  • კომენტარი — როლის დაზუსტება ან შენიშვნა (მაგ. „შემოწმებას ამტკიცებს ცვლის ხელმძღვანელი“). დამთვალიერებელი მას ხედავს ყველა ნაბიჯის „ვინ“ ბარათზე.
ბმულები და პასუხისმგებლები ინახება ტექნიკური იდენტიფიკატორითაც (XML ID). ამიტომ სხვა ბაზაში გადატანის შემდეგ სტანდარტული მენიუები ისევ სწორად იხსნება, ხოლო რაც ვერ მოიძებნა, დიაგრამაზე მოინიშნება როგორც გაწყვეტილი.

9.პროცესის ბარათი, დონე, თეგები

პროცესის ბარათი ჩანართი აღწერს პროცესს SIPOC-ის ლოგიკით: გამშვები მოვლენა, მომწოდებლები, შემავალი, გამავალი, მომხმარებლები, და ინდიკატორები (KPI) — რა იზომება, სამიზნე, სიხშირე და მონაცემთა წყარო. KPI-ის სამიზნეების შეცვლა გამოქვეყნებულ ვერსიაშიც შეიძლება; დანარჩენი ბარათი ვერსიის ნაწილია.

ველიმნიშვნელობა
პროცესის ტიპიძირითადი (საოპერაციო), დამხმარე, მმართველობითი — სტანდარტული კლასიფიკაცია (Porter-ის ღირებულების ჯაჭვი, ISO 9001-ის პროცესული მიდგომა). ახალი ტიპების დამატება არ არის საჭირო; დამატებითი ჭრილებისთვის გამოიყენეთ თეგები.
დონეპროცესების არქიტექტურის სიღრმე APQC PCF-ის მსგავსად: L0 ღირებულების ჯაჭვი/კატეგორია → L1 პროცესების ჯგუფი → L2 პროცესი → L3 ქვეპროცესი → L4 აქტივობა/პროცედურა. მშობლის არჩევისას დონე თავად იწევს ერთით.
თეგებითავისუფალი, ფერადი ჭრილები (ISO 9001, მომხმარებელთან ურთიერთობა, კრიტიკული…). მართვა: კონფიგურაცია → თეგები.

10.იმპორტი: draw.io, Visio, BPMN

პროცესები → დიაგრამის იმპორტი (ან დრაფტის ფორმაზე ღილაკი დიაგრამის იმპორტი — არსებული დიაგრამის ჩასანაცვლებლად).

წყაროროგორ მოვამზადოთ ფაილი
draw.io / diagrams.netFile → Save as → .drawio (ან .xml). გამოდგება File → Export as → SVG / PNG, თუ მონიშნულია „Include a copy of my diagram“. მრავალგვერდიან ფაილში თითოეული გვერდი ცალკე პროცესი ხდება (ან აირჩიეთ „მხოლოდ პირველი გვერდი“).
Microsoft VisioFile → Save As → Visio Drawing (*.vsdx). ძველი .vsd ჯერ უნდა შეინახოთ .vsdx-ად.
Camunda Modeler, Signavio, bpmn.io, Bizagi, ARIS…BPMN 2.0 XML ექსპორტი (.bpmn). თუ ფაილს განლაგება არ აქვს, გახსნისას ავტომატურად განლაგდება.

რას ცნობს გადამყვანი

  • draw.io-ს BPMN 2.0 ბიბლიოთეკის ყველა ფიგურას, swimlane-ებს, Cross-Functional Flowchart-ს;
  • Visio-ს BPMN Diagram შაბლონის ფიგურებს (shape data-ს მიხედვით), Cross-Functional Flowchart ზოლებს, Basic Flowchart-ს;
  • ჩვეულებრივ ნახაზებს: მართკუთხედი → ამოცანა, რომბი → გამომრიცხავი შლუზი, წრე/ოვალი → მოვლენა, დოკუმენტი → მონაცემთა ობიექტი, ცილინდრი → მონაცემთა საცავი, ტექსტი → შენიშვნა;
  • ფერებს: ფიგურის შევსება და ხაზის ფერი (თეთრი/შავი ნაგულისხმევი ფერები არ გადმოდის, რომ დიაგრამამ მოდულის სტილი შეინარჩუნოს).

რა ხდება იმპორტის შემდეგ

  1. ზოლები ედარება დეპარტამენტებს, თანამდებობებს და ჯგუფებს ზუსტად იმავე სახელით. ნაპოვნი ავტომატურად მიებმება.
  2. ყველა ზოლი ინიშნება ! ნიშნით: „დაადასტურეთ ავტომატური შერჩევა“ ან „მიანიჭეთ დეპარტამენტი / როლი“. ვარაუდით განსაზღვრული ფიგურებიც ინიშნება („შეამოწმეთ ელემენტის ტიპი“).
  3. chatter-ში იწერება ანგარიში: რა გარდაიქმნა, რა გამოტოვდა და რატომ.
რჩევა: draw.io-ში გამოიყენეთ More Shapes → BPMN 2.0 ბიბლიოთეკა და შემაერთებლები ფიგურებზე მიამაგრეთ. Visio-ში გამოიყენეთ BPMN ან Cross-Functional Flowchart შაბლონი. ზოლებს დაარქვით ზუსტად Odoo-ს დეპარტამენტის სახელი — მაშინ ისინი ავტომატურად მიებმება.

ზოლების შესაბამისობის თავიდან გასაშვებად (მაგ. დეპარტამენტების შექმნის შემდეგ) დრაფტზე დააჭირეთ ზოლების შესაბამისობა.

11.გადასახედი რიგი

მენიუ გადასახედი რიგი აგროვებს ყველა პროცესის მონიშნულ ელემენტს: რა უნდა გაკეთდეს და სად. გახსნა გადაგიყვანთ პროცესზე და პირდაპირ ამ ელემენტს მონიშნავს.

დიაგრამის ზედა ზოლში ღილაკი ⚠ გადასახედი: N თანმიმდევრულად გადადის მონიშნულ ელემენტებზე; მიმოხილვის პანელშიც არის მათი სია. შესწორების შემდეგ დააჭირეთ გადახედულად მონიშვნა; ზოლზე პასუხისმგებლის არჩევისას ნიშანი თავად იხსნება. ნიშნებს ხედავს მხოლოდ პროცესების მენეჯერი.

12.დამტკიცება, ვერსიები, კონტროლი

სტატუსივინ ხედავსრედაქტირებაშემდეგი ნაბიჯი
დრაფტიმენეჯერებიდიახგანხილვაზე გაგზავნა / გამოქვეყნება
განხილვაშიმენეჯერებიარაგამოქვეყნება / დრაფტში დაბრუნება
გამოქვეყნებულიყველაარაახალი ვერსია / გაუქმება
გაუქმებულიმენეჯერებიარა—
  • ახალი ვერსია (1.0 → 1.1) და ახალი ძირითადი ვერსია (1.x → 2.0) ქმნის გამოქვეყნებულის დრაფტ ასლს (დიაგრამა, ბარათი და KPI-ები ჩათვლით). ახლის გამოქვეყნებისას ძველი ავტომატურად „გაუქმებული“ ხდება — ისტორია არ იკარგება (ღილაკი ვერსიები).
  • ერთდროულად მხოლოდ ერთი ვერსია შეიძლება მზადდებოდეს. გამოქვეყნება ჩაიწერება chatter-ში.

პერიოდული გადახედვა

ვერსია და გადახედვა ჩანართში მიუთითეთ გადახედვის პერიოდი (თვე) (ნაგულისხმევად 12). გამოქვეყნებისას ითვლება შემდეგი გადახედვის თარიღი; ვადის დადგომისას პროცესის მფლობელი იღებს დავალებას (to-do) „პროცესის პერიოდული გადახედვა“, თარიღი კი შემდეგ ციკლზე გადადის. ფილტრი გადასახედი ვადა დადგა აჩვენებს ვადაგადაცილებულ პროცესებს.

გაცნობის დადასტურება

თუ ჩართულია გაცნობის დადასტურება, გამოქვეყნებულ პროცესზე თანამშრომელს უჩანს ღილაკი გავეცანი. დადასტურება ინახება ვერსიის მიხედვით: ახალი ვერსია ხელახლა გასაცნობია. მენეჯერი ხედავს ღილაკს გაეცნო N და სრულ სიას (კონფიგურაცია → გაცნობის დადასტურებები).

14.ხშირი კითხვები

რატომ არ ჩანს ჩემი პროცესი რუკაზე?

რუკაზე მხოლოდ გამოქვეყნებული პროცესებია. დრაფტები და განხილვაში მყოფი ვერსიები ჩანს ყველა პროცესი მენიუში (მხოლოდ მენეჯერებს).

რატომ არ შემიძლია დიაგრამის შეცვლა?

რედაქტირება შესაძლებელია მხოლოდ დრაფტში და მხოლოდ პროცესების მენეჯერისთვის. ზედა ზოლში ● მხოლოდ ნახვა-ზე მიტანილი კურსორი გეტყვით, რა უნდა გააკეთოთ (ახალი ვერსია ან დრაფტში დაბრუნება).

მალსახმობები არ მუშაობს

დააწკაპუნეთ დიაგრამის ცარიელ ადგილზე — მალსახმობები მუშაობს, როცა დაფა აქტიურია. Ctrl+S მუშაობს პანელის ველებშიც.

ყველაფერი ზუსტად გადმოვა draw.io-დან/Visio-დან?

BPMN ბიბლიოთეკით დახაზული ნახაზი — თითქმის სრულად, ფერების ჩათვლით. თავისუფალი ნახაზის დროს მოდული ფიგურის ტიპს ვარაუდობს და ასეთ ფიგურებს გადასახედად ნიშნავს. შრიფტები და ხაზების ზუსტი მოხვევები არ გადმოდის: შემაერთებლები ორთოგონალურად გადაიხაზება.

რა არ არის მხარდაჭერილი

  • Visio-ს ძველი .vsd ფორმატი (შეინახეთ .vsdx-ად); Visio-ში ექსპორტი;
  • BPMN Choreography და Conversation დიაგრამები;
  • პროცესის ავტომატური შესრულება (ეს არ არის workflow engine — განზრახ);
  • დიაგრამის შინაარსის (სახელები, ინსტრუქციები) მრავალენოვნება.

რა არის „BPMN.io“ ლოგო კუთხეში?

დიაგრამის ბიბლიოთეკის (bpmn-js) ლიცენზია მოითხოვს, რომ ეს ლოგო ხილული დარჩეს. მისი დამალვა ლიცენზიას არღვევს.

15.ადმინისტრატორისთვის

  • ინსტალაცია / განახლება: ფოლდერი bpmn_process_management დაამატეთ addons path-ში → Apps → Update Apps List → „BPMN Process Management“ → Install (ან განახლებისას Upgrade). დამატებითი Python პაკეტები არ სჭირდება.
  • როლები: ყველა შიდა მომხმარებელი ავტომატურად არის დამთვალიერებელი; პროცესების მენეჯერი ენიჭება მომხმარებლის ფორმაში.
  • ენა: ადმინისტრატორი ერთხელ ააქტიურებს ენას (Settings → Languages → Add Language), შემდეგ თითოეული მომხმარებელი ირჩევს მას My Preferences → Language-ში. მოდულის მთელი ინტერფეისი, რედაქტორისა და ეს სახელმძღვანელოს ღილაკების ჩათვლით, გადაირთვება. თარგმანი: i18n/ka.po; ახალი ენისთვის — i18n/bpmn_process_management.pot.
  • დაგეგმილი მოქმედება: „Business Processes: periodic review reminders“ ეშვება დღეში ერთხელ (Settings → Technical → Scheduled Actions).
  • მულტიკომპანია: „კომპანია“ ცარიელი = პროცესი ყველა კომპანიისთვის; შევსებული = მხოლოდ იმ კომპანიისთვის. KPI-ები და დადასტურებები მიჰყვება პროცესს.
  • დეპარტამენტებთან კავშირი: ჩაირთვება, თუ დაინსტალირებულია Employees (hr). Knowledge და Documents ბმულები — Enterprise-ში, თუ ეს აპლიკაციები დაყენებულია.
