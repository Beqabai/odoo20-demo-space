## ნაწილი II. მოქმედი ტექნიკური დავალება

### 1. მიზანი და ფილოსოფია

მოდული არის ორგანიზაციის პროცესების **საცავი, მოდელირების ინსტრუმენტი და ცოდნის ბაზა** (Single Source of Truth).
ის **არ არის** Workflow Execution Engine: არ ბლოკავს ღილაკებს, არ ცვლის სხვა დოკუმენტების სტატუსებს და არ ერევა
გაყიდვების, შესყიდვების, საწყობისა და ბუღალტერიის ლოგიკაში.

### 2. თავსებადობა

- Odoo **19.0** და **20.0**, Community და Enterprise; ერთი საკოდო ბაზა.
- დამოკიდებულებები: მხოლოდ `base`, `web`, `mail`.
- არჩევითი ინტეგრაცია (თუ დაინსტალირებულია): `hr` (დეპარტამენტი, თანამდებობა), `knowledge` და `documents` (Enterprise).
- გარე ფორმატები: BPMN 2.0 XML (Camunda Modeler, Signavio, bpmn.io, Bizagi და სხვ.), draw.io, Microsoft Visio (.vsdx).

### 3. როლები და წვდომა

| როლი | ვინ | უფლებები |
|---|---|---|
| დამთვალიერებელი (`group_process_user`) | ყველა შიდა მომხმარებელი (ავტომატურად `base.group_user`-იდან) | ხედავს მხოლოდ **გამოქვეყნებულ** პროცესებს, კითხულობს ინსტრუქციებს, ხსნის ბმულებს. ჩაწერის უფლება არ აქვს. |
| პროცესების მენეჯერი (`group_process_manager`) | ანალიტიკოსი, ხარისხის მენეჯერი | ქმნის, არედაქტირებს (მხოლოდ დრაფტს), აიმპორტებს, გზავნის განხილვაზე, აქვეყნებს, ქმნის ახალ ვერსიას. |

დამატებით: მულტიკომპანიური წესი (`company_id` ცარიელი = საერთო ყველა კომპანიისთვის).

### 4. მონაცემთა მოდელი

**`business.process`** — პროცესის ერთი ვერსია:
`name`, `code`, `version`, `state` (draft → review → published → deprecated), `category` (ძირითადი/დამხმარე/მმართველობითი),
`parent_id` (პროცესების იერარქია), `owner_id`, `company_id`, `description` (HTML), `bpmn_xml` (Text, BPMN 2.0),
`diagram_preview` (SVG მინიატურა), `root_id` / `previous_version_id` (ვერსიების ჯაჭვი), `published_date` / `published_by_id`, chatter.

**`business.process.element`** — დიაგრამის ელემენტების საძიებო ინდექსი. ყოველი შენახვისას თავიდან იგება XML-იდან
(XML რჩება ერთადერთ წყაროდ): ტიპი, სახელი, ზოლი, აუზი, პასუხისმგებელი, ბმულების რაოდენობა, გადახედვის სტატუსი და მიზეზი.
იძლევა ძიებას „რომელ პროცესებში მონაწილეობს საწყობის დეპარტამენტი?“ და კვებავს „გადასახედ რიგს“.

**`business.process.import`** — იმპორტის ოსტატი (TransientModel).

**v1.1 დამატებები:**

| ველი / მოდელი | დანიშნულება |
|---|---|
| `level` (L0–L4) | პროცესების არქიტექტურის დონე (APQC PCF-ის ლოგიკით); მშობლის არჩევისას +1 |
| `tag_ids` → `business.process.tag` (name, color) | თავისუფალი ჭრილები (ISO 9001, კრიტიკული…). `category` რჩება სამ სტანდარტულ მნიშვნელობად (ძირითადი/დამხმარე/მმართველობითი — Porter, ISO 9001) |
| `trigger`, `supplier`, `process_input`, `process_output`, `customer` | პროცესის ბარათი (SIPOC), ვერსიის შინაარსის ნაწილი (იკეტება) |
| `kpi_ids` → `business.process.kpi` (name, target, frequency, source) | ინდიკატორები; ახალ ვერსიას გადაყვება; გამოქვეყნებულშიც რედაქტირებადი |
| `review_interval`, `next_review_date` + ყოველდღიური cron | პერიოდული გადახედვა: ვადაზე მფლობელს ექმნება to-do, თარიღი შემდეგ ციკლზე გადადის |
| `ack_required`, `ack_ids` → `business.process.ack` (process, user, version, date) | „გავეცანი“: დადასტურება ვერსიის მიხედვით; დამთვალიერებელი ხედავს მხოლოდ საკუთარს, მენეჯერი — ყველას |

### 5. სასიცოცხლო ციკლი და ვერსიები

1. **დრაფტი** — რედაქტირდება დიაგრამა, სახელი, კოდი, აღწერა.
2. **განხილვაში** — შინაარსი იკეტება; შეიძლება დრაფტში დაბრუნება.
3. **გამოქვეყნებული** — ხილულია ყველასთვის; ამავე ჯაჭვის წინა გამოქვეყნებული ვერსია ხდება „გაუქმებული“; chatter-ში იწერება ჩანაწერი.
4. **ახალი ვერსია** (1.0 → 1.1) / **ახალი ძირითადი ვერსია** (1.x → 2.0) — იქმნება გამოქვეყნებულის ასლი დრაფტად.
   ერთდროულად მხოლოდ ერთი ვერსია შეიძლება მზადდებოდეს.

შეზღუდვა სერვერზეა (არა მარტო ინტერფეისში): დრაფტის გარდა სხვა სტატუსში `name`, `code`, `bpmn_xml`, `description`, `category`, `level` და პროცესის ბარათის ველები არ იცვლება.

### 6. Odoo-სთან მსუბუქი კავშირები (Soft Linkage)

მეტამონაცემები ინახება BPMN-ის სტანდარტულ `<bpmn:extensionElements>` ტეგში, საკუთარ namespace-ში
`http://gecbusiness.com/schema/bpmn/odoo/1.0` (პრეფიქსი `odoo`). გარე პროგრამები მათ უცვლელად ტოვებენ.

| ელემენტი | Odoo-ს ობიექტი | შენახვა |
|---|---|---|
| ზოლი / აუზი | `hr.department`, `hr.job`, `res.groups`, `res.users` | `<odoo:responsible model="…" resId="…" xmlid="…" name="…" note="…" syncName="true"/>` — `note`: როლი/კომენტარი; `syncName`: ზოლის სახელი მიჰყვება პასუხისმგებელს |
| ფერები | — | სტანდარტული `color:background-color` / `color:border-color` (OMG non-normative) + `bioc:fill` / `bioc:stroke` |
| ნებისმიერი ფიგურა | Odoo-ს მენიუ (`ir.ui.menu`), ფანჯრის მოქმედება, ჩანაწერი (`knowledge.article`, `documents.document`, `business.process`, `ir.attachment`), URL | `<odoo:link linkType="menu|action|record|url" …/>` (რამდენიმეც შეიძლება) |

| გადასახედი ნიშანი | — | `<odoo:review status="pending" reason="…" source="drawio|visio|import"/>` |

### 7. ინტერფეისი

- ველის ვიჯეტი `bpmn_editor` (Text ველზე). ორი რეჟიმი:
  - **დამთვალიერებელი** — `NavigatedViewer`. გვერდითი პანელი: პროცესის მიმოხილვა (სტატისტიკა, „პროცესის გავლა ნაბიჯ-ნაბიჯ“, ნაბიჯის ძებნა, „ვინ რას აკეთებს“) ან ნაბიჯის ბარათი (ვინ + კომენტარი, ინსტრუქცია სიების ფორმატირებით, ბმულების ფილები, წინა/შემდეგი ნაბიჯები შლუზის პირობებით). მიმდინარე ნაბიჯი და შემდეგი ნაბიჯები დიაგრამაზე ინთება.
  - **რედაქტორი** — `Modeler` (მენეჯერი + დრაფტი). პანელი: სახელი სათაურში, ტიპის შეცვლა (bpmn-replace), გადასახედი შეტყობინება, პასუხისმგებელი (ზოლის ავტომატური სახელი, კომენტარი, სინქრონიზაცია), ინსტრუქცია, ბმულები, ნაკადი, სტილი (9 მზა ფერი GEC-ის პალიტრით + ნებისმიერი შევსება/ხაზი, გაუქმება); რამდენიმე ელემენტზე — სწორება/განაწილება და ერთობლივი ფერი.
- ხატვის კომფორტი (bpmn-js 18.30 + bpmn-io-ს MIT დამატებები): დასაკავშირებლად დასაშვები ფიგურების განათება ისრის გაყვანისა და გადაბმისას (BPMN წესებით), კონტეინერების განათება ფიგურის ჩასმისას, „ელემენტის დამატება/შექმნა“ ძებნით (`A`/`N`), ფერების context pad, მინირუკა, ბადე, სნეპინგი და დამხმარე ხაზები, ტექსტის სიგანის შესწორება გარე წარწერებისთვის.
- კლავიატურა: bpmn-js-ის სტანდარტული მალსახმობები + `Ctrl/⌘+S` შენახვა (პანელის ველებშიც), `?` დახმარება, `F` სრული ეკრანი, `P` პანელი, `M` მინირუკა, `G` ბადე, `0` მორგება.
- ხელსაწყოების ზოლი: სტატუსი (რედაქტირება/მხოლოდ ნახვა + მინიშნება), დაბრუნება/გამეორება, ძებნა, „გადასახედი: N“, ჩამოტვირთვა, მინირუკა, ბადე, მალსახმობები, სახელმძღვანელო, პანელი, სრული ეკრანი; მასშტაბი — ქვედა მარცხენა მცურავი ბლოკი.
- ენა: ინტერფეისი (bpmn-js-ის ტექსტების ჩათვლით) მიჰყვება მომხმარებლის ენას; ქართულისთვის ზედა რეგისტრი (Mtavruli) გამორთულია.
- სახელმძღვანელო მოდულშია: `static/doc/user_guide.html` — მენიუ „სახელმძღვანელო“ და რედაქტორის „?“ ღილაკი.
- „პროცესების რუკა“ — kanban ბარათები მინიატურით, დონით, კოდით, თეგებით, სტატუსით, ვერსიით, მფლობელით.
- „გადასახედი რიგი“, „პასუხისმგებლობები“, „კონფიგურაცია → თეგები / გაცნობის დადასტურებები“.
- აპლიკაციის ხატულა Odoo-ს სტილშია (გადაფარებული ფიგურები: მოვლენა, ამოცანა, შლუზი) GEC-ის ფერებით.
- ვიჯეტი ტექნიკურად დამოუკიდებელია OWL-ის ვერსიისგან: OWL ფენა მხოლოდ DOM ელემენტს აწვდის ჩვეულებრივ JS კლასს; ჩანაწერის განახლებები თანმიმდევრულად მუშავდება და ძველი მნიშვნელობის „ექო“ (Odoo 20-ის onchange) იგნორირდება.

### 8. იმპორტი და ექსპორტი

| ფორმატი | რას ცნობს |

ანგარიში (რა გამოტოვდა და რატომ) იწერება chatter-ში.

**ექსპორტი:** `.bpmn` (ვალიდური OMG BPMN 2.0, იხსნება Camunda Modeler-სა და Signavio-ში), `.drawio` (draw.io-ს BPMN ფიგურებით,
